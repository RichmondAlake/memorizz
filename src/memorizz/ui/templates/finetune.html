How fine-tuning works
  1. Collect examples. Generate them with a teacher LLM (a blind second check keeps only the ones it agrees with), import your stored memories, or add your own. Accept the ones that look right.
  2. Train. Training runs on this machine (Apple GPU, CUDA or CPU) with LoRA, or with Unsloth on an NVIDIA GPU. Each run is scored before and after on test examples it never trained on.
  3. Compare and swap in. Each card under Models in use compares the best fine-tuned version with what runs now, on the same test examples. Swap it in with one click and swap back any time.

Decision models answer a typed question about a piece of state with a probability per option (the System One contract of Jev, Clef and pplx-decider): memory routing picks the store a memory belongs in; relevance says whether a memory helps answer a query. Embedding models put each query near the memory that answers it. Rerankers rescore the memories vector search found, so the best evidence comes first.

Continual learning: train a new version from an earlier one with new data, replay some earlier data so it keeps what it knew, and judge every version on the same test sets (datasets that are only scored on, never trained on).

Python: FineTuning(provider) · CLI: memorizz finetune · MCP: memorizz_*_finetune_*
